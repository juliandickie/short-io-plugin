# Short.io REST API audit - 16 September 2026

Every endpoint the plugin depends on, exercised live against a real account with a secret
key. Throwaway links were created on a test path and deleted at the end; the final expand
confirmed they are gone. Account-specific ids are not recorded here on purpose (the raw
log is kept locally, untracked).

Base URL `https://api.short.io`. Header `authorization: <bare key>`. Requests carrying no
header, or the key behind a `Bearer ` prefix, both answer 401 `{"error":"Unauthorized"}`.
The hosted MCP server answers the same mistake with `Unauthorized: No API key provided`.

## Rate limits are per endpoint family, read from headers

| Family | `x-ratelimit-limit` | Endpoints seen |
|---|---|---|
| Listing | 1000 | `GET /api/domains`, `GET /api/links` |
| Link creation | 50 | `POST /links` |
| Link info and delete | 20 | `GET /links/expand`, `GET /links/:id`, `GET /links/multiple-by-url`, `DELETE /links/:id` |

`x-ratelimit-remaining` and `x-ratelimit-reset` (seconds) accompany every answer. The
earlier "30 per 60 seconds" figure belongs to the MCP endpoint, not REST.

## Endpoints

### GET /api/domains

200, JSON array. Useful keys per domain - `id` (number), `hostname`, `linkType`
(`eight-char` or `random`), `redirect404` (null when unset), `state` (`configured`).
`GET /api/domains/:id` is not a route (404 `Route GET:/api/domains/<id> not found`).

### GET /api/links?domain_id=<number>&limit=<n>[&pageToken=<token>]

200 `{count, links[], nextPageToken}`.

- `domain_id` is required and numeric. Passing `domain=<hostname>` answers 400
  `must have required property domain_id`.
- `limit` maximum is 150. 151 and above answer 400 `limit must be <= 150`.
- `count` is the true total for the domain, present on every page.
- `nextPageToken` is a string on every page but the last, where it is absent. Pass it back
  as `pageToken`. Tokens look like `page_...`.
- Link keys - `id, idString, path, displayPath, originalURL, shortURL, secureShortURL,
  title, tags, archived, cloaking, hasPassword, skipQS, source, createdAt, updatedAt,
  DomainId, OwnerId, User`.

### GET /links/expand?domain=<hostname>&path=<slug>

200 with the link record when the slug exists. 404 `{"error":"Link not found"}` when it is
free, and again after the link is deleted. `domain` here is the hostname, not the id.

### GET /links/multiple-by-url?domain=<hostname>&originalURL=<url-encoded>

200 `{links[]}` - every link on the domain whose destination equals the URL exactly. This
is the dedupe-by-destination check. Records carry `slugSuggestions` and `tagSuggestions`
in addition to the usual keys. No `count`, no paging.

Correction, 2026-11-05 - this audit recorded only the case with a match. With no match the
answer is 404 `{"error":"No links found"}`, and with an unknown domain it is 404
`{"error":"Domain not found"}`.

### GET /links/<idString>

200 with the record.

### POST /links

Body `{domain, originalURL, path?, title?, tags?[]}`; `domain` is the hostname.

| Case | Answer |
|---|---|
| New path | 200, the record (`idString`, `shortURL`, `path`, timestamps) |
| Existing path, same originalURL | 200, the EXISTING record, no error, nothing created |
| Existing path, different originalURL | 409 `{"message":"Link already exists","statusCode":409,"success":false}` |
| No path, originalURL already shortened on the domain | 200, the EXISTING random-path record, nothing created |
| No path, new originalURL | 200, a new random path (eight characters on an `eight-char` domain) |
| `originalURL` not a URL | 400 `originalURL must pass "url" keyword validation` |
| Unknown domain | 404 `{"message":"Domain not found","statusCode":404,"success":false}` |

So the API dedupes silently on (path, destination) and on (destination alone when no path
is given). A script that trusts a 200 as "created" will over-count. The plugin compares
`createdAt` against the request time, and checks `expand` first, so a silent return of an
existing record is reported as `exists`, not `created`.

### DELETE /links/<idString>

200 `{"success":true,"idString":...}`. A second delete answers 404
`{"success":false,"error":"Link not found"}`. Expand after delete answers 404.

## Live redirect behaviour of a short domain

Fetching `https://<domain>/<slug>` without following redirects, on a domain with a
default fallback configured, answers 302 to the fallback page for an unknown slug AND for
a real one. Status code and even the redirect target cannot distinguish a working link
from a typo when the fallback is the same site. Only `expand` tells the truth. The
plugin's `check` command therefore reports the configured destination first, then the live
answer, and probes one random unused slug on the domain to tell the user whether their
domain has a 404 or a fallback.

## Error body shapes

Three shapes appear - `{"error": "..."}` (401 on REST, 404 on expand and delete),
`{"message": "...", "statusCode": n, "success": false}` (409, 400 validation, 404
domain), and Fastify validation `{"statusCode", "code": "FST_ERR_VALIDATION", "error",
"message"}`. The client reads `message`, then `error`, for the human string.
