# Live smoke - 16 September 2026

Read-only checks against the real Short.io account with the key resolved from
`~/.config/short-io-plugin/config.toml` (mode 600). Nothing was created, edited, or deleted.
API keys, domain ids, and link ids are redacted below; `idd.to` is a public hostname so it is
named as-is.

## CLI

### whoami

```
$ ./bin/short-io whoami
key source: file
id             hostname       type           links
<redacted>     <domain-1>     eight-char     <count>
<redacted>     idd.to         eight-char     284
<redacted>     <domain-3>     random         <count>
exit=0
```

The key never appears in the output, only its source (`file`).

### links, full pagination

```
$ ./bin/short-io links idd.to --json | node -e "...print count, listed, links.length"
count 284 listed 284 links 284

$ ./bin/short-io links idd.to --include-archived --json | node -e "...same"
count 284 listed 284 links 284
```

The API `count` (284) equals the number of links actually fetched across every page, so the
pager reaches the end. This account has no archived links on `idd.to`, so `--include-archived`
returns the same 284 rather than a larger set.

### check, a slug that does not exist

```
$ ./bin/short-io check idd.to/definitely-free-slug-for-smoke
idd.to/definitely-free-slug-for-smoke
  configured: FREE (no link with this slug)
  live:       HTTP 302 -> https://instituteofdigitaldentistry.com
  fallback:   unknown slugs redirect to https://instituteofdigitaldentistry.com (no 404 on this domain, a typo fails silently)
  verdict:    free-but-redirects
exit=0
```

`idd.to` has a domain-level 404 redirect, so an unknown slug answers 302 rather than 404. The
verdict is `free-but-redirects`, not `ok`, and the fallback line spells out why a typo on this
domain fails silently.

### check, a slug that exists

```
$ ./bin/short-io check idd.to/ios-price-guide
idd.to/ios-price-guide
  configured: https://<a flipbook host>/<redacted>.html
  live:       HTTP 302 -> https://<a flipbook host>/<redacted>.html
  fallback:   unknown slugs redirect to https://instituteofdigitaldentistry.com (no 404 on this domain, a typo fails silently)
  verdict:    ok (served as a redirect)
exit=0
```

The JSON form of the same call returns `verdict: "ok"`, `served: "redirect"`, the link title,
and the `fallback` block with the random `probedPath` used for the probe (id redacted here).

## Bridge tool call, scripted

`scripts/bridge-smoke.mjs` spawns `scripts/run-mcp.mjs` the way Claude Code would
(`CLAUDE_PLUGIN_ROOT` at the repo, `SHORT_IO_PLUGIN_DATA` at a scratch data dir holding the
pinned `mcp-remote`), speaks MCP over its stdio, and runs `initialize`, `tools/list` and a
`tools/call` of `get-domains`. The key is resolved by the launcher from the config file; the
script never reads it and never prints ids. Hostnames other than the public `idd.to` are
redacted below to match the rest of this record.

```
$ node scripts/bridge-smoke.mjs
```

not just the launcher starting.
